## Q1: Why 2048 bits?

RSA-2048 protects **peer identity in LAN collaboration** — not long-term secrets. 2048 is fast on XO devices; 4096 adds delay. OpenSSH used 2048 as default for this use case.

## Q2: How are existing keys replaced?

**They're NOT replaced** — they're preserved. Here's what happens:

**New profiles:** Generate RSA-2048 (line 82 change)  
**Existing DSA profiles:** Keep working (guard at line 65 skips generation if key exists)  
**Migration:** Toolkit loads both DSA and RSA when present

| Scenario | Result |
|----------|--------|
| DSA ↔ RSA-only | ❌ Fails |
| DSA ↔ DSA+RSA | ✅ Works |
| RSA ↔ DSA+RSA | ✅ Works |

**Solution:** Multi-key toolkit loads both types, prefers RSA, falls back to DSA.

def _load_all_pubkeys(self):
    keys = []

        keypath = os.path.join(self.path, key_type + '.pub')
        if os.path.exists(keypath):
